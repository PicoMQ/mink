# Statistics

Mink publishes a distinct-value estimate for each column of a topic's table, as Apache DataSketches theta sketches in an Iceberg statistics file. Cost-based planners, Trino's and Spark's among them, read it. It never affects which files a query reads. This document pins how the sketches are built during indexing without reading Kafka again, how they are kept, and the statistics file the writer publishes.

## Columns

Every primitive column of the topic's latest table schema that is not inside a list or a map has a sketch, the binary columns `_kafka_partition`, `_kafka_offset`, `_kafka_timestamp`, `_kafka_key` and `_kafka_value` included.

## Sketches

A sketch is an Apache DataSketches update theta sketch with `lg_k` 12 and the default seed 9001. A column's non-null values update it as their Iceberg single-value binary encoding, the same bytes as `file.md` Stats bounds but never truncated. An empty encoding (an empty string or binary) does not update it, as DataSketches skips empty input. NaN updates it like any other value.

The indexer builds each column's sketch for the records of the files it adds, while it builds their bytes, and unions it into the topic's stored sketch for the UTC day of each record's `_kafka_timestamp`. It does so in the same transaction as `Files::add`, so a stored sketch holds the values of exactly the files added. Assembly adds no values, so it leaves the sketches as they are.

A stored sketch is the compact, ordered, uncompressed serialization: the bytes datasketches-java and datasketches-cpp read.

## Statistics file

Every `statistics_interval` the writer publishes the sketches with its next commit:

1. It unions, per column, every stored day sketch. With none stored, nothing is published.
2. It writes a Puffin file, `{location}/metadata/{N}-e{E}-stats.puffin` for snapshot `N` and lease epoch `E`, with one uncompressed blob per column. Each blob is of type `apache-datasketches-theta-v1`, with `fields` `[field id]`, `snapshot-id` and `sequence-number` `N`, and the property `ndv`: the union's estimate rounded to the nearest integer.
3. Snapshot `N`'s table metadata lists that file as its only `statistics` entry, with its path, length, footer length and blob metadata. The statistics file listed before is released.
4. After the commit it trims the stored days: `Sketches::trim` deletes every day before the UTC day of the smallest `first_timestamp_ms` among the live files (`file.md` Stats), read under the ranges' locks so a file an indexer adds meanwhile keeps its days.

A planner looking for statistics walks back from the snapshot it reads to the nearest snapshot with a statistics file. It finds one as long as a kept snapshot carries it, so `statistics_interval` must stay below `snapshot_retention`.

Days of whole records that Kafka's retention has removed stay in the sketches until their day is past the smallest live `first_timestamp_ms`, and a published union holds the days the previous trim kept; the estimate then overstates by at most those days' distinct values. A statistics file whose snapshot expires is released and no longer listed, until the next publication.

## Settings

| Setting | Default | Meaning |
| --- | --- | --- |
| `statistics_interval` | `1h` | How often the writer publishes a statistics file; below `snapshot_retention` |

## Errors

| Error | When |
| --- | --- |
| `sketch` | A stored sketch does not deserialize, or was built with another seed |

## Invariants

1. Sketches are built from the values the indexer already holds; nothing reads Kafka for them.
2. A sketch Mink writes is read unchanged by datasketches-java and datasketches-cpp, and holds the hashes they would compute for the same values.
3. A table's statistics file describes the files of a snapshot no older than `statistics_interval` before its latest.

## Conformance

- `conformance/fixtures/statistics/sketches.json`: sets of byte strings and the serialized sketch Apache DataSketches' Python package (datasketches-cpp) builds from them. Its updates take strings and 64-bit integers, so the byte strings are ones a string carries unchanged (bytes below `0x80`) and 64-bit integers' little-endian bytes, the encoding of an Iceberg `long`; the sets are large enough to leave exact mode. Generated by `python -m sketches` in `mink/mink-conformance`, never by Mink.
- `mink-core` `sketch::tests::sketches_match_datasketches`: invariant 2: Mink's sketch of each fixture's byte strings is byte for byte the fixture's.
- `mink-core` `sketch::tests::unions_count_each_value_once`: a union of overlapping sketches.
- `mink-iceberg` `file::tests::values_update_as_their_single_value_encoding`: the update bytes of the binary schema's `int`, `long`, `timestamptz` and `binary` columns equal iceberg-rust's `Datum::to_bytes`; typed columns share each type's encoder with its bounds, which `table::tests::the_metadata_loads_in_iceberg_rust` and the typed bounds test read back through `Datum`.
- `mink-iceberg` `table::statistics::tests::the_statistics_file_is_valid_puffin`: the Puffin layout, read back by iceberg-rust's Puffin reader.
- `mink-store` `sketches::tests::concurrent_unions_lose_nothing`: two indexers unioning into one day's sketch.
- `mink-conformance` `pyiceberg_reads_the_statistics_file`: PyIceberg lists the statistics file, and each blob's sketch deserializes in Apache DataSketches with the estimate its `ndv` states.
